# 编程与技术任务

知远智能体可以在项目文件夹中阅读和修改代码、运行开发命令，并结合编程学习、代码审查、安全检查、性能分析和前端设计等技能完成技术任务。可用能力取决于当前系统、项目依赖和所选模型。

## 进入项目工作

持续处理一个代码仓库时，先在工作页面选择“进入项目工作”，再使用现有项目文件夹。这样可以把文件操作限制在明确目录中，也方便后续任务沿用项目上下文。

开始前建议确认工作区状态，并使用版本控制或其他方式保留可恢复的基线。不要把磁盘根目录、包含多个无关项目的上级目录或存有私人文件的目录作为项目范围。

## 描述技术任务

除了目标，还应提供：

- 运行环境、语言和主要框架版本。
- 问题的复现步骤、错误信息和预期行为。
- 可以修改与不能修改的目录。
- 需要执行的测试、构建或格式检查命令。
- 是否允许安装依赖、联网、改动配置或提交版本记录。

例如：

> 修复设置页在窗口变窄时按钮消失的问题。先阅读现有布局和样式，保持桌面与移动端共用一套结构，只修改设置页相关文件。完成后运行现有前端测试和构建，不安装新依赖，也不要提交 Git 记录。

范围不明确时，可以先让知远只分析原因和列出方案，确认后再授权修改。

## 检查代码改动

执行过程中留意命令、权限请求和文件列表。涉及删除、覆盖、依赖安装、数据库迁移、外部部署或 Git 推送时，应先确认具体影响。

完成后检查：

1. 改动是否只涉及约定范围。
2. 关键路径是否有测试或可重复的验证步骤。
3. 构建、类型检查和格式检查是否通过。
4. 是否意外加入生成文件、缓存、凭据或调试代码。
5. 错误处理和平台差异是否被覆盖。

安全和性能类技能可以帮助发现问题，但扫描结果可能包含误报，也可能漏掉依赖环境才能触发的问题。重要改动仍需代码评审、测试和实际运行验证。

## 保护凭据和生产环境

不要在任务正文、截图或仓库文件中粘贴访问令牌、私钥和生产密码。需要凭据的工具应使用项目既有的安全配置方式。生产部署、数据写入和对外发布属于外部操作，应单独说明目标环境并逐步确认。
