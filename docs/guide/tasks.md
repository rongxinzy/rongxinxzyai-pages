# 创建和执行任务

一项可执行的任务应说明目标、输入、交付物和边界。知远智能体会根据这些信息读取资料、调用工具并形成结果；缺少关键条件时，任务可能停下来请求确认。

## 写清任务

任务描述可以按下面四部分组织：

1. **目标**：要解决什么问题。
2. **资料**：应使用哪些文件、链接或背景信息。
3. **交付物**：最终需要文档、表格、演示文稿、代码还是文字结论。
4. **边界**：哪些内容不能修改，是否允许联网，是否可以执行命令或发送内容。

例如：

> 阅读项目目录中的三份访谈记录，按用户角色归纳共同问题，输出一份 Markdown 总结。保留原文件，不访问外部网站；无法判断的内容单独列出。

这类描述比“帮我整理一下”更容易检查，也能减少执行过程中对范围的猜测。

## 执行前检查

提交任务前确认：

- 当前模型可以正常响应，并具备任务需要的工具或图片能力。
- 文件已经添加，或项目目录已经选定。
- 需要使用的技能处于启用状态。
- 权限模式符合当前资料的重要程度。

任务包含多个独立交付物时，可以先让知远列出执行顺序，再分阶段完成。涉及大量文件、外部发送或不可逆操作时，不要把所有权限一次性放开。

## 查看执行过程

工作页面会持续显示消息、工具状态和权限请求。出现权限请求时，先检查操作对象和影响范围，再选择允许或拒绝。

如果方向已经偏离，可以停止当前任务，补充要求后重新开始。工具显示成功不等于交付物已经正确，仍需查看内容、文件路径和格式。

## 检查和继续修改

结果生成后，按原始要求逐项核对：

- 是否使用了指定资料。
- 是否遗漏关键条件。
- 文件是否保存在预期位置。
- 表格公式、引用、链接和代码是否可用。
- 是否发生了未授权的外部访问或写入。

需要修改时，直接指出具体位置和目标，例如“保留前两节，只重写结论，并把表格中的金额改为万元”。同一工作页面中的后续任务可以沿用前文，但关键约束仍应再次写明。

需要补充输入材料时，继续阅读[添加文件与上下文](./context.md)。
