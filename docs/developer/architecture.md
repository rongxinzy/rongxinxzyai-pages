# 项目结构

知远智能体使用 Electron 和 React 构建。Electron 主进程负责本地服务、存储和系统能力，渲染进程负责界面；两者通过受控的 preload 与 IPC 通信。

## 桌面应用目录

| 路径 | 用途 |
| --- | --- |
| `src/main/` | Electron 主进程、服务、存储和 IPC 处理 |
| `src/main/preload.ts` | 主进程与渲染进程之间的受控接口 |
| `src/renderer/` | React 界面、状态和渲染进程服务 |
| `src/shared/` | 跨模块类型、工具和共享界面组件 |
| `src/scheduledTask/` | 自动化任务的领域逻辑与常量 |
| `SKILLs/` | 随应用发布的内置 Skill |
| `MCPs/` | 随应用提供的 MCP 集成 |
| `scripts/` | 开发、运行时准备和打包脚本 |

修改前先从用户操作入口找到渲染端组件，再沿 preload、IPC 类型和主进程处理器定位数据流。不要因为某个界面文件较大，就绕过现有边界直接访问系统能力。

## 进程边界

渲染进程不能直接使用 Node.js 或 Electron API。需要新增系统能力时，应同时检查并更新：

1. 共享类型和 IPC 通道常量。
2. `src/main/preload.ts` 暴露的受控方法。
3. 主进程处理器和业务服务。
4. 渲染端调用与错误状态。
5. 相关的单元测试和中英文界面文案。

保持这条链路完整，可以避免把文件系统、进程或凭据能力暴露给页面上下文。

## 任务数据流

用户在工作页面提交任务后，渲染进程通过 IPC 启动或继续任务。主进程中的任务运行时处理消息、工具调用和权限请求，再把流式内容、工具状态、完成或错误事件发送回界面。会话和配置等数据保存在本地 SQLite 中。

本地推理、Skill 管理、MCP、自动化和消息渠道也由主进程服务管理，并通过各自的受控接口向界面提供状态。涉及写文件、执行命令或外部发送的操作，应保留现有权限和确认机制。

## 官网目录

官网仓库与桌面应用独立：

| 路径 | 用途 |
| --- | --- |
| `src/` | React 官网页面和共享导航 |
| `docs/` | VitePress 文档源码 |
| `docs/.vitepress/` | 文档站配置与主题扩展 |
| `functions/` | Cloudflare Pages Functions |
| `public/` | 官网静态资源 |
| `dist/` | 官网与文档的构建输出 |

官网使用根路径，文档站部署在 `/docs/`。新增链接和资源时，应同时考虑开发环境、源码 Markdown 预览和该部署基路径。
