# 问题排查

遇到问题时，先判断故障发生在哪一层：应用是否正常启动，模型能否响应，技能和工具是否可用，文件是否能读取，以及任务要求是否清楚。按顺序检查比连续重试更容易定位原因。

## 先记录现场

在关闭应用或修改配置前，记录：

- 知远版本，可在“设置”→“关于”中查看。
- 操作系统和设备架构。
- 使用的模型提供商、模型 ID，或本地模型名称。
- 问题出现前的操作步骤。
- 完整错误提示和出现时间。
- 涉及的文件类型、大小和数量。

不要在截图、日志或问题描述中公开 API Key、邮箱授权码、访问令牌和原始敏感资料。

## 按顺序检查

1. **确认应用状态**：如果无法安装、启动或更新，查看[安装与更新](./install.md)。
2. **测试模型**：新建任务并发送一句简单文本。没有响应时，查看[模型连接](./model.md)。
3. **减少任务变量**：暂时移除非必要文件和技能，用最小任务复现问题。
4. **检查技能**：确认技能已经安装、启用，并满足模型和依赖要求。查看[技能使用](./skills.md)。
5. **检查文件**：确认文件已经添加，格式能被当前任务处理，并且没有超出上下文。查看[文件处理](./files.md)。
6. **重新启动**：模型或智能体运行服务连接中断时，保存当前工作后重启应用，再重试最小任务。

任务停在权限请求时，需要先查看操作对象和影响范围，再决定允许或拒绝。界面显示工具完成，也不代表最终文件已经正确生成，应继续检查结果内容和保存路径。

## 提交问题反馈

问题可以稳定复现时，请在 [RongxinAI GitHub Issues](https://github.com/rongxinzy/RongxinAI/issues) 中搜索是否已有相同报告，再提交版本、系统、复现步骤、预期结果和实际结果。

应用可以打开时，可在“设置”→“关于”中导出日志。分享前检查日志和附件，移除凭据、个人信息和不应公开的文件内容。
